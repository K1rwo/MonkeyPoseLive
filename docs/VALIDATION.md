# v0.1.0 验证范围

此页记录软件工程核查，不评价模型的解剖准确率或动物的内在情感。

## 已完成的源码检查

- 40项Python检查：最新帧和轨迹逻辑7项、配置解析与完整性16项、真实loopback配置API9项、桌面包装与发布资产隔离8项。
- 15项离线前端回归：包含原有10项实时配置／轨迹竞态检查，以及首次缺模型、路径设置、JSON修复和运行中禁止改模型环境。
- Python 3.12桌面源码实际启动本机HTTP服务，验证资源读取、OpenCV／NumPy编码、初始idle、5后端清单、控制令牌和服务退出；未打开摄像头或模型。
- 使用已存在的15秒短片，独立配置后的W32＋CPU YOLO实际集成检查通过：按原时间采集224帧、处理146帧；重复改变ROI时丢弃在途旧结果，保留17原始通道／15显示点，关闭保存时无坐标文件，临时输入和工作进程退出正常。
- 配置迁移后的ViTPose、X-Pose、DLC均实际常驻加载，每个模型接收两条既有图片请求、一条非法ROI请求和停止；原生点位、有限坐标、异常处理和工作进程退出通过，模型检查点散列未变。自包含AP10K专家／解码头选择与原始张量一致。该检查不测稳定视频帧率。

私有实验媒体、路径、配置和逐帧结果仅保留在本地受控目录，不发布到本仓库。

## Windows EXE 实测

- 64位Python 3.12构建的便携EXE通过实际headless自检：内置HTTP、资源、OpenCV／NumPy、五后端声明、鉴权关闭和端口释放。
- Microsoft EdgeChromium独立桌面窗口实际加载MonkeyPoseLive页面，再自动关闭；自有HTTP服务退出，未启动摄像头或模型。
- 使用EXE自带服务和用户配置的外部MacaquePose Python，W48 CUDA＋CPU YOLO完成15秒猴子短片模拟：采集224帧、处理110帧，保留原生17点；调整阈值后ROI保持，坐标保存关闭时不写JSONL／CSV，工作缓存清除，模型进程结束。软件与外部模型环境使用隔离的依赖目录。

早期打包测试发现外部Python误导入桌面包的扩展库；发布版把工作进程源码放在独立backend目录，隔离工作目录、Python搜索路径和DLL环境后，重新冻结并完成上述实测。研究素材和错误日志均未进入发布包。

## 设备与模型边界

原型阶段已实际运行五个模型适配器，软件版的W32源码链路、W48冻结EXE链路及另三个模型适配器已分别完成上述运行检查。不能把静态图耗时或短片模拟结果换算成目标摄像头的稳定性能。

USB摄像头硬件没有在本轮打开。目标相机的编号、驱动、曝光／缓冲延迟、长时间运行和关键点质量需要在实际采集现场验证。软件只提供单猴2D自动预测；不保证遮挡点、目标身份或情感状态正确。
